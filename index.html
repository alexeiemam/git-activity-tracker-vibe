Run inside your repository. This fetches tags from origin, adds GitHub Releases via authenticated gh (when available), and copies commit history without a committer-date cutoff. No GitHub token or API response is sent to git:signals; the import stays in your browser. The command uses macOS pbcopy; on other systems, remove the final pipe and copy terminal output.

SHOW AREA ACTIVITY AS

For GitHub-published releases, the publication timestamp locates the event and the publisher is an assumed release driver; the publisher is not proof of who deployed. Lightweight Git tags have no tagger identity. Publishers are automatically linked only when imported Git identities give an unambiguous exact match; manual assignments override inference. The date scope is shared: contribution counts use authored dates, while release events use GitHub publication dates when available (otherwise annotated-tag or tagged-commit dates). Tagged release contents are reconstructed from the Git ancestry graph, independent of merge commits or VERSION changes. File revisitation, test accompaniment, codebase breadth and commit-subject categories are proxies, not proof of value, production deployment, code quality or hours worked.
