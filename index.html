05 / THE WORKING RHYTHM

Different patterns. Same window.

Day-of-week and time-of-day distributions for each selected contributor, based on commit timestamps rather than line volume.

Within-person percentages describe when their commits occurred (not their relative contribution). Times reflect each commit's authored local clock. Missing timestamps are excluded only from time-of-day proportions.

06 / THE SHAPE OF CHANGES

How big were the changes?

Within-person mix of commit sizes: a shared 100% scale, alongside actual commit counts and median change size.

Groups use measured added + removed text lines per commit. Zero includes binary-only changes and commits without numstat entries. Size is not a proxy for effort or quality.

07 / WHERE THE WORK WENT

Codebase hotspots.

Top-level folders grouped by file touches, with selected people compared against the same reference group.

Files in the repository root appear under “(root)”. A file touched in multiple commits counts multiple times. Binary file changes count as touches but not line churn.

08 / THE UNDERLYING EVENTS

Recent commits in this slice.

Evidence to check the charts against. Only commits matching the global filters appear.

Interpretation guide. Git logs measure recorded changes—not effort, difficulty, effectiveness, or code quality. A commit's authored date may differ from its integration date. Merge detection uses parent hashes when available (subject heuristics for older logs). “VERSION touches” is a repository-specific proxy, not a verified release count. All comparisons are scoped to the imported history; they do not include uncollected branches or missing dates.
